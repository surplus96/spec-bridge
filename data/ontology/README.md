# 합성 데이터 작성·정답 판정 기준

2026-10-06 작성 · 2026-10-07 v2 갱신 · DATA-CONTRACT · origin: synthetic

[dataset-contract.yaml](dataset-contract.yaml)은 데이터셋을 작성하고 정답의 표현 가능성을 확인하기 위한 간이 온톨로지 명세다. 제품 분류 6종, 상위 계층, 속성 27종, 자료형·정규 단위·차원, 조건·기준·관계와 합성 등록 준비 정책을 담는다. 로더·추출기·애플리케이션 검증기는 구현하지 않는다.

v2에서는 FourStrokeEngine.application의 propulsion/genset, Separator.application의 fuel_oil/lube_oil을 **합성 등록 지원 용도의 닫힌 목록**으로 정의했다. E4 사례 작성용 정책이며 실제 용도의 완전한 분류가 아니다. 다른 속성의 열거 후보는 여전히 닫힌 목록으로 확정하지 않았다.

## 적용 방법

1. 주 제품의 말단 클래스를 선택하고 상위 클래스의 속성을 함께 적용한다.
2. 원문에 있는 값만 라벨링한다. 조건·출력 대상·중량 포함 범위·원문 단위와 위치를 함께 기록한다.
3. 명세의 required_all/required_any_groups/conditional_required는 **합성 데이터의 등록 준비 판정 정책**으로 사용한다. 실제 제품의 법적·기술적 필수 요건으로 주장하지 않는다.
4. 다른 조건의 값은 별도 사실로, 같은 사실의 반복 표기는 여러 근거로 보존한다. 불명 조건끼리 동일하다고 가정하지 않는다.
5. 평가 정답에는 누락·오류 판정의 이유와 위치를 기록하되 입력 사양서에는 작성 시나리오·정답·오류 라벨을 붙이지 않는다.

속성 의미와 원본 표기 근거는 [6개 클래스 정의표](../../docs/ontology-scope/README.md) 및 [판본·페이지 근거](../../docs/ontology-scope/reference-evidence.yaml)를 참조한다. 단위 차원은 정규 정답의 작성 기준이며 전역 단위 환산 사전이나 물리적 허용 범위를 제공하지 않는다. bhp/BHP·ton의 해석은 문서의 명시적 정의에 따른다.

열거형 후보는 실제 업계 전체를 포괄하는 닫힌 목록으로 확정하지 않았다. 예를 들어 pump_type의 centrifugal/three_screw는 현재 필수 분기의 조건이며, 다른 원문 표현은 원문·unknown/검토 이유를 보존한다. 새로운 분기를 채택할 때는 명세 버전을 갱신한다.

## 현재 정답과의 연결

기존 후보 6건은 정답 schema_version 2, dataset_revision 2를 유지한다. 대표 속성 55개와 조건부 값 1개, 총 **56개 채점 단위**가 이 명세에서 표현된다. 속성 사실의 근거는 98개이며, 관계 근거까지 포함한 기존 감사의 99개 위치와 집계 대상이 다르다.

`reported_weight`, `differential_pressure`, `discharge_pressure`, `working_pressure`는 새 사례 작성에서 사용할 확장 속성이다. 기존 6건에 이 라벨을 추가하거나 선택 속성 누락을 오류로 재분류하지 않았다. 기존 expected_status/missing_required는 null, validation_status는 ontology_pending을 유지한다. 향후 판정 라벨을 확정할 때 정답·채점 정책·명세 버전을 함께 기록한다.

이 6건은 설계 과정에서 참고했으므로 독립 테스트셋으로 집계하지 않는다. 작성 명세는 개발·테스트 공통 기준이 될 수 있으나, 테스트 정답과 사례별 설계 메모는 모델 입력·프롬프트·사전 구성에 넣지 않는다.

## 데이터 품질 점검

저장소 루트에서 현재 로컬 Python의 PyYAML을 사용한다.

```bash
python data/eval/reviews/check_dataset_contract.py
```

[점검 결과](../eval/reviews/dataset-contract-checks.json)는 ID·상속·필수 참조·정규 단위·현재 정답의 자료형·근거 존재를 확인한다. 조건의 실제 기술적 의미, 단위 환산의 정확성, 근거 문구의 실제 위치, 누락·중복 판정까지 검사하는 도구는 아니다. 원문 위치·환산 등 기존 후보의 점검은 별도의 [감사 스크립트](../eval/reviews/review_dataset.py)에서 수행한다.

## 데이터셋 확정까지 남은 작업

- [신규 본셋 사례·분할 계획](../synth/README.md)을 작성했다. 40건 슬롯을 예약했으며 실제 문서는 아직 생성하지 않았다.
- 사양서 40건(PDF 20·Excel 12·DOCX 8), 등록 목록 150건, BOM 4건, 중복·유사 정답 쌍 10건을 구성한다.
- 정상 최소 10건, 조건별 복수 값·반복·미기재·단위/형식 불일치 등 평가 목표를 배분한다. 별도 함정 목록은 만들지 않는다.
- 생성 파일의 실제 페이지·시트·셀·표 위치와 정답을 대조한다.
- 채점 기준과 분할·버전·해시를 고정하고 데이터셋 검토 패키지를 작성한다. 사용자 의미 검증·서명은 별도이며 자동으로 채우지 않는다.

외부 분류 코드 연결과 기능 코드 구현은 이번 데이터셋 완성의 선행 조건이 아니다. 이미 작성한 공통 모델 참고 코드는 구현 자료로 보관하며 데이터셋 완성도에 포함하지 않는다.
