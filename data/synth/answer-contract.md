# 본셋 정답 기록 계약 v3

[answer-contract.yaml](answer-contract.yaml)은 신규 본셋의 정답 작성 기준이다. 현재 수기 후보 6건의 정답 v2와 채점 정책은 유지한다. **이 계약은 실제 문서의 정답 파일이 아니며, 구현 스키마·추출기·검증기도 아니다.**

## 원문에서 정답을 만드는 방법

먼저 문서를 읽고 각 출현을 observations에 기록한다. 원문의 값·단위·라벨·위치와 해석 상태를 보존한다. 정규화 근거가 충분한 출현만 facts로 연결하고, 문제가 있으면 issues에 규칙과 이유를 남긴다. 합성 제품 원장은 의도한 제품 정보이며 문서에 없거나 틀리게 적힌 값을 대신 채우는 정답 근거가 아니다.

| 사례 | 관찰 | 정규 사실 | 판정 |
|---|---|---|---|
| 정상·V1 | 모든 실제 출현 보존 | 같은 사실의 반복은 근거 여러 개로 연결 | 기술 표기 변형 자체는 오류가 아님 |
| E1 | 없는 항목의 가짜 출현을 만들지 않음 | 해당 속성 없음 | 문서 해시·점검 위치·적용 필수 규칙을 기록 |
| E2 | 값과 잘못된 단위를 그대로 보존 | 해당 잘못된 출현에는 정규 사실 없음 | 기대 차원과 원문 차원의 차이 |
| E3 | 문자열/역전 범위와 parsed_value 보존 | 값 추정·범위 끝점 자동 교정 없음 | 자료형·객체 구조 위반 |
| E4 | 명시된 허용 목록 밖 용도 보존 | 문자열 사실 유지, unsupported_value 표시 | 합성 지원 용도 정책 위반 |
| E5 | 상충하는 출현 모두 보존 | 동일 조건의 상충 값들을 모두 유지 | 조건·기준·범위의 동일성을 근거로 제시 |

예를 들어 출력 항목에 `48 rpm`이라고 쓰였다면 관찰에는 해당 문자열과 위치를 남긴다. 단위를 kW로 바꾸거나 원장의 출력값을 복사해 정답 사실을 만들지 않는다. 이는 설명용 합성 예시이며 본셋의 실제 라벨이 아니다.

같은 조건에서 다른 두 값이 나오면 어느 쪽이 맞는지 추측하지 않는다. 둘 모두 정답의 상충 값 집합이다. 반대로 서로 다른 주파수·점도·정격점은 별도 정상 사실이며 E5가 아니다. 중요한 조건이 unknown이면 같다고 가정하지 않고 unresolved/검토 이유를 남긴다.

원문에 전체 범위와 그 범위 내 한 값이 함께 있으면 자동으로 E5라고 판정하지 않는다. 대표 사례 계획은 목표 라벨이며 실제 문서 내용이 그 라벨을 지지하는지 작성 후 다시 확인한다.

## 분리해서 채점할 항목

클래스 매핑, 정규 사실, 원문 관찰 회수, 오류 판정, 지정된 중복·유사 쌍을 각각 보고한다. E2/E3의 잘못된 출현은 정규 사실 분모에서 제외되지만 관찰·오류 판정 분모에 남는다. 각 채널의 실제 분모를 공개하며 예상 약 400개 속성을 실제 정답 개수로 사용하지 않는다.

같은 문서·속성·조건·기준·범위 아래의 값 집합을 정규 사실 채점 단위로 한다. E5의 상충 값 두 개를 모두 회수해야 그 집합이 일치한다. 반복 출현은 정규 사실 점수를 늘리지 않으며 위치 회수율로 따로 평가한다. 다른 조건의 정상 값은 별도 집합이다. 범위·치수는 객체 단위, 연료 목록은 순서 없는 집합으로 비교한다.

기본 수치 허용차는 합성 채점 정책으로 절대 0.000001·상대 0이다. 문서에서 정의한 환산·반올림이 있으면 문서별 허용차를 평가 전에 명시한다. 조건·단위·범위가 다르면 수치만 비슷하다고 일치로 처리하지 않는다.

## 중복·유사 정답의 범위

현재 예약한 10개 비교 쌍만 duplicate/similar 정답을 작성한다. E6는 실제 제품 ID와 제조사·모델이 같고, E7는 같은 합성 계열의 다른 제품이며 의도한 차이를 기록한다. 계열 ID는 작성·평가기 메타데이터이므로 비교용 등록 입력에 노출하지 않는다.

원장에는 같은 계열의 여러 제품이 있으므로 지정 대상 외에도 유사 제품이 존재할 수 있다. 따라서 **미지정 쌍을 new/음성으로 간주하지 않고, 이 10쌍을 단일 정답의 검색 순위 평가로 사용하지 않는다.** 전체 목록 대비 new/duplicate/similar 판정이나 top-k 검색 평가는 추가 정답 범위·음성 쌍을 확정한 뒤 수행한다.

## 실제 파일과 최종 확정

PDF는 실제 페이지와 영역/절, Excel은 시트·셀 범위, DOCX는 문단/표 셀에 연결한다. 실제 파일 해시와 근거 위치 확인 상태를 기록한다. 원본 레퍼런스 PDF의 페이지는 합성 문서의 근거 위치가 아니다.

정답은 문서 내용에서 대조해 작성하고 수동 검토 뒤 파일·분할·명세 해시를 고정한다. 생성 원장과 문서가 같은 자료로 만들어진다는 이유만으로 정답 정확성을 확정하지 않는다. reviewed_by는 사용자 검토 전까지 null이다.
