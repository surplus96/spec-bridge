2026-10-16 · 작성: 헬퍼 모델 · 상태: **검토 대기**. 헬퍼는 통과 판정을 하지 않는다(H2-4). 결과는 [decisions.md](../decisions.md)에 `CP-S4`로 기록한다. 공개는 이 검토가 끝난 뒤 사용자가 새 저장소로 한다(D-080 결정 5, D-094).

## 1. 배경 (5줄)

1. spec-bridge는 선박 기자재 사양서에서 온톨로지 사실(값 + 기준·조건·범위)을 추출·검증하고, 담당자 검토 뒤에 등록하는 로컬 도구다. 데이터는 모두 합성이다.
2. W4-R에서 값마다 해결 사례를 검색하는 RAG 체인(E1SV)이 개발 분할에서 문맥 해석을 풀었다(F1 0.946, D-053). W5에서 검토 화면과 등록을 만들었다.
3. W6에서 시스템을 해시로 동결하고(D-086), 개발 재현(D-087) 뒤 테스트 16건과 수기 사양서 6건을 한 번씩 실행했다(D-089, D-090).
4. 결과: 테스트 E1SV F1 0.913, 사전 등록 기준 (a)~(c)·목표권 성립(사용자 판정). 수기 세트는 목표권 미달이라 ③ 미성립. G3는 0.875로 미달(원인 수용).
5. 평가 뒤에 검토 화면 보완(D-091), 오프라인 관찰(D-092), CI 대조(D-093), 원문 PDF 추적 중단(D-094), 공개 문서(D-095)를 했다. 이 검토로 공개 여부와 문서의 주장 수위를 정한다.

## 3. CP-S4 검토 질문 (계획서 H4)

### 질문 1. G1~G5 보고가 수치로 재현되는가?

**근거**
- 동결 해시: 채점기 `f9b6e223cb15`, 프롬프트 모듈 5개, RAG 모듈 5개, KB `cfc116a6…`, 온톨로지, 개발 사전, 수기 세트 12파일·변환기·Markdown 리더. 테스트·수기 실행은 해시가 다르면 거부된다(`freeze.py`).
- 모든 W6 실행의 `run.json`에 동결 시각, 해시, 모델 digest `c7c4e3d1ca22`가 있다. 실패 0, 클라우드 호출 0이다.
- 동결 시스템이 개발 분할 이전 수치(D-053)를 그대로 재현했다(D-087). 테스트·수기 실행 10개를 재채점한 결과가 실행 기록과 같다.
- 보고서 §8에 재현 명령이 있다. `compare`를 다시 실행해 (a)·(c) 값이 같게 나오는 것을 확인했다.

**재현 명령**
```bash
uv run python -m spec_bridge.eval.freeze verify
uv run python -m spec_bridge.eval.rescore var/eval/test-*-20261015T* var/eval/handwritten-*
uv run python -m spec_bridge.eval.compare --e1 var/eval/test-E1SV-20261015T060851Z --e0 var/eval/test-E0-20261015T054216Z --r var/eval/test-R-20261015T051146Z
uv run python -m spec_bridge.eval.errors var/eval/test-*-20261015T* var/eval/handwritten-*
```

**검토자가 볼 점**
- 원자료 `var/eval/`은 커밋하지 않는다. 새 저장소에서 수치를 다시 만들려면 같은 digest의 모델과 약 2시간의 실행이 필요하다. 실행 원자료(예측 JSON·감사 기록, 합성 데이터만 담김)를 공개 저장소에 포함할지는 사용자 결정 사항이다.
- `compare` CLI는 (b)·목표권 기준값을 개발용 상수(16, 50)로 출력한다. 테스트 기준(≤ 10, ≥ 38)은 보고서 표로 대조한다.

### 질문 2. 합성 데이터·원문 미커밋·출처 표기가 지켜졌는가?

**근거**
- README 첫 화면과 모델·데이터 카드에 합성 데이터 고지가 있다. 합성 제조사는 `SGDW-… Synthetic Works`이고, 온톨로지·사전은 `origin: synthetic`이다.
- 참고 제조사 문서 12건은 manifest(제목·출처 URL·판본·sha256·`verified_by`)만 추적한다.
- `tests/test_no_originals.py`가 네 가지를 검사한다.
  - 추적 파일 중 참고 문서 sha256과 같은 파일이 없어야 한다.
  - 문서 파일은 합성 입력 폴더에만 있어야 한다.
  - 백업 압축에 참고 문서가 없어야 한다.
  - 추적 텍스트에 홈 디렉터리 경로가 없어야 한다.
- 비밀 키 패턴과 `.env`는 추적 파일에 없다.

**반드시 볼 점 — 이력 문제(D-094)**
- 참고 PDF 12개(복제 금지 고지)가 **첫 커밋 `d4b3a1e`부터 추적됐고 기존 원격 저장소에 푸시됐다.** 지금은 추적을 끊었지만 과거 커밋에는 남아 있다.
- 결정된 대응은 기존 저장소를 비공개로 유지하고, 정리된 상태를 새 저장소의 첫 커밋으로 공개하는 것이다(2b). 기존 저장소는 비공개다(사용자 확인, 2026-10-16).
- 검토 요청: 새 저장소로 옮길 때 포함·제외할 목록이 충분한가. 예를 들어 `data/backups/*.tgz`(합성 스냅샷, 다른 작업자 후보 포함), `docs/archive/`, 결정 기록 속 조사 출처 URL이 있다.

## 4. 헬퍼가 확신이 낮은 지점

- **L1 소표본 부트스트랩**: 테스트 16건, 수기 6건에 문서 단위 쌍체 부트스트랩을 썼다. 수기 (c) 구간 [0.286, 0.622]처럼 넓다. 목표권 문턱을 `ceil(0.515 × 키 수)`로 계산했다(37.08 → 38). 사전 등록 문구 "51.5% 이상"의 해석으로 맞는지 봐 달라.
- **L2 오류 원인 분류 순서**: `errors.py`는 놓친 키와 남는 키를 value → context → attribute → value_and_context 순으로 짝짓는다. 순서를 바꾸면 일부가 다른 원인으로 갈 수 있다. 합계는 채점기와 같다.
- **L3 문맥 차이의 알림 범위**: D-091 확인에서 "문맥 차이 대부분에 '문맥 확인 필요' 표시"라고 한 것은 어림값이다. 모델이 제시했다가 거부된 문맥이 같은 속성에 있는지만 봤고, 화면의 위치 대조를 그대로 재현하지 않았다. 보고서와 공개 문서에서는 수치로 인용하지 않았다.
- **L4 평가 뒤 기능 추가**: 사전 밖 값 경고(D-091)는 테스트·수기 오답을 보고 만들었다. 평가 수치에는 영향이 없지만, "담당자에게 간다"는 주장은 같은 데이터로 확인한 사후 결과다.
- **L5 오프라인 관찰**: 1초 간격 `lsof`로 1회 관찰했다. 짧은 연결은 Python 소켓 감시 테스트가 보완하지만, 네이티브 확장과 자식 프로세스는 그 감시 밖이다.
- **L6 비교 행 A·B·C**: 실행 스크립트 오류로 문맥 필수형이 돌았다(D-089). 공개 표에서는 "필수형"으로 표기했다. 독자가 "LLM 단독은 F1 0.03"으로 오해할 여지가 남는지 봐 달라.
- **L7 CI 미실행**: GitHub Actions는 실제로 돌지 않았다. 깨끗한 복제본과 프로젝트 가상환경으로 같은 선택을 돌렸다. Linux 설치는 PyPI torch와 CUDA 패키지 15개 때문에 느릴 수 있다.
- **L8 G5 표현 수위**: 케이스 스터디 §3은 "사례가 어휘 해석을 가르친다"고 쓴다. 근거는 합성 데이터의 개발·테스트 결과다. 수기 세트(1/13)는 반대 신호다. 표현 수위가 적절한지 봐 달라.

## 5. 전제·가정

- 판정 기준은 D-080에서 실행 전에 등록했고, 판정은 사용자가 했다(D-090).
- 개발 분할 조정은 생성 단계 3회, 검색 설정 0회다. 동결 뒤 시스템 조정은 0회다. D-091·D-092는 평가 수치에 쓰이지 않는 운영 코드만 바꿨고, `freeze verify`는 일치한다.
- 수기 사양서는 헬퍼 초안이고 독립성이 낮다(D-080 결정 1, D-082).
- 클라우드 모델은 테스트 분할에 쓰지 않았다.

## 7. 검토 결과 기록 방법

검토 결과를 받으면 decisions.md에 `날짜 · CP-S4 · 지적 사항 · 조치 · 미해결`로 기록하고, `docs/reviews/cp-s4-review-result.md`에 원문을 남긴다. 공개 문서의 표현을 고쳐야 하면 수치는 보고서에서 다시 가져온다. 지적 사항을 해결한 뒤 사용자가 공개 여부를 결정한다.
