# BOM 표기 원문·출처·패턴 검토 (2026-10-17)

검토자: Codex. 사용자가 “이번 작업에 한해 Codex 검토 서명을 verified_by에 허용하기”를 선택했다(D-106). 이 승인은 아래 8개 출처와 12개 패턴에 한정한다.

## 원문 대조

로컬 PDF의 SHA-256을 manifest와 비교하고, 43개 발췌를 지정된 쪽의 렌더링 화면에서 확인했다. 별도로 쪽별 PDF 텍스트와 공백을 정규화한 부분 문자열 대조를 수행해 43개 모두 일치했다. 이 검사는 문서의 표기를 확인하는 것이며, 선박의 실제 장비 사양이나 제조사 별칭의 정확성을 보증하지 않는다.

| 출처 | raw-examples 행 순번(1부터) | 쪽 | 확인한 발췌 수 |
|---|---|---|---:|
| BOMSRC-01 | 1–12 | 1 | 12 |
| BOMSRC-02 | 13–21 | 1 | 9 |
| BOMSRC-03 | 22–28 | 2–3 | 7 |
| BOMSRC-04 | 29–30 | 2–3 | 2 |
| BOMSRC-05 | 31–36 | 1 | 6 |
| BOMSRC-06 | 37–40 | 1 | 4 |
| BOMSRC-07 | 41–42 | 1 | 2 |
| BOMSRC-08 | 43 | 1 | 1 |

- 9행의 모델 표기 내부 공백을 PDF 텍스트 계층의 좁은 줄바꿈 방지 공백(U+202F)으로 복원했다. 원문의 철자 차이와 오타로 보이는 표현은 교정하지 않았다.
- `raw_text`는 장비 항목의 연속 발췌다. 칸 경계·줄바꿈은 공백으로 연결하며, 전체 칸이나 문장을 모두 수록했다는 뜻은 아니다. 예를 들어 11·23·25·28·32·33행에는 뒤따르는 사양이 더 있다. 36행은 원문에서 다음 펌프 설명과 붙어 있는 부분의 앞 장비 발췌이며 이를 한 장비의 전체 사양으로 해석하지 않는다.
- BOMSRC-01·02의 판본은 파일명 날짜가 아니라 PDF 하단의 2025-07-28 rev 1.0으로 기록했다.
- BOMSRC-04 제목을 PDF 표지에 맞췄다. 표지 제목의 길이와 치수·본문의 길이가 서로 다른 사실은 edition에 기록하고 어느 값이 맞는지 추정하지 않았다.
- BOMSRC-05·06의 파일명 판본·날짜는 본문에서 확인한 판본과 구분했다.
- 행별 결과·이전/이후 패턴 태그·원본 해시·검토한 raw 파일의 해시는 로컬 `data/reference/bom/review-results.yaml`에 남겼다. 원문과 이 상세 기록은 git 제외 대상이다.

## 이용 조건과 서명

8개 `license_note`를 모두 채웠다. 확인일, 근거 URL 또는 PDF 쪽, 확인된 제한과 허가 미확인 상태를 기록했다. 원문 대조 서명은 권리자가 부여한 이용 허가가 아니다.

- Britoil: PDF의 정확성 비보증·변경 가능성을 확인했다. [공식 조건](https://www.britoil.com.sg/terms-conditions)은 구매·서비스 주문에 관한 것이어서 웹 제원표의 재사용 허가로 적용하지 않았다.
- Ocean Marine: [이용약관 페이지](https://www.oceanmarine.com/terms)는 준비 중이며 저작권 유보를 표시한다. 공개 재사용 허가는 확인되지 않았다.
- Transhipment Services: PDF에서 재사용 허가를 확인하지 못했고 [홈페이지](https://www.transhipmentservices.com.au/)에는 저작권 표시가 있다.
- Young Brothers: [이용약관](https://htbyb.com/terms/)은 서면 동의 없는 체계적·자동 데이터 수집을 제한한다. 이번 대조는 사용자 제공 로컬 PDF를 대상으로 했으며 추가 자동 수집 권한을 확보한 것으로 기록하지 않았다.
- Damen: PDF 2쪽 하단에 서면 허가 없는 복제 제한이 명시되어 있다. 별도 서면 허가는 확보하지 않았다. 근거 문서는 manifest의 source_url과 SHA-256으로 식별한다.
- Swiftships: PDF에서 재사용 허가를 확인하지 못했고 [홈페이지](https://swiftships.com/)에는 저작권 유보 표시가 있다.

원문·발췌는 로컬에 유지하고 공개용 파일에는 출처 정보와 자체 작성 패턴 설명만 둔다. 로컬 보관 자체를 이용 허가의 근거로 삼지 않는다.

## 패턴 확정

PAT ID 12개를 유지했다. PAT-04는 표의 칸뿐 아니라 문단의 사양을 포함하고, PAT-07은 제조사와 모델이 모두 빠진 경우도 표현하도록 이름을 바꿨다. PAT-05·06은 관찰된 명칭 형태·철자 차이를 기술하며 동일 제조사 판정이나 철자 정정으로 해석하지 않도록 고쳤다.

| PAT-02 | quantity_in_parentheses | 일반 |
| PAT-03 | quantity_bare_number | 일반 |

37행은 모델 내부 구분자가 없어 PAT-11을 제거했다. 원문으로는 유효하므로 행을 유지하고 패턴 목록을 비웠다. 다른 행의 사양·모델 구분자 태그와 철자 차이의 양쪽 관찰 근거를 보완하고, 각 패턴의 source_refs를 실제 태그가 있는 행의 출처·쪽에서 다시 구성했다. 일반 패턴은 문서 2개 이상에서 관찰됐다는 기존 기준이며 제조사·발행 주체 독립성을 뜻하지 않는다.

## 정리와 검증

- `iTermBrowserPlugin-1.0.zip`을 열거나 실행하지 않고 삭제했다.
- 집계 결과: 출처 8, 발행 주체 6, 원문 행 43, 패턴 유형 12, 일반 패턴 10, 단일 출처 패턴 2. 수량 조건은 `ready: true`다. 이용 허가 확보나 G5 실험 재개 승인을 뜻하지 않는다.
- 기존 테스트의 “수집 자료가 없으므로 항상 ready=false” 가정을 제거했다. 공개 체크아웃을 재현하도록 없는 raw 파일 경로를 주고, 로컬 원문 없이는 준비 완료로 판정하지 않는지 확인한다.
- 기본 CLI와 pytest 실행은 작업 전부터 진행 중이던 `dedup` 이동에 따른 `spec_bridge.dedup` import 실패로 막혔다. 검증 프로세스에서만 옛 패키지 경로를 현재 `spec_bridge/extract/dedup`으로 연결했을 때 BOM 점검 및 관련 테스트 15개가 통과했다. 저장소의 해당 리팩터링 파일은 수정하지 않았다. 기본 실행 경로의 성공은 확인되지 않았다.
- 8개 원본 해시 일치, 43개 쪽별 발췌 일치, 패턴별 출처 참조 일치, 원본 미추적 검사와 변경 파일 공백 검사를 확인했다.
