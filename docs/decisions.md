## D-005 · 2026-10-06 · 6개 클래스 유지와 기능·평가 중심 진행 순서 확정

- **결정**: 사용자 결정에 따라 `6개 클래스 유지 → 온톨로지 범위 확정 → 클래스별 사례 다양화 → 주요 기능과 평가 완성` 순서로 진행한다. D-002의 말단 클래스 6개를 유지하며, 지원 범위는 해당 선박 기자재의 제품 정보 생성·등록 자동화다.
- **근거**: 사용자가 제공한 과제 원문의 간이 온톨로지, 가상 사양서 30~50건, 추출·정규화·검증·중복 검사·검토·등록 요구. 선박 제조 도메인의 모든 기자재 클래스를 포괄해야 한다는 요구는 제공된 원문에 없다.
- **진행 기준**: 현재 12건의 원본을 근거로 속성·조건·기준을 정의하고, 6건의 보완된 합성 문서는 초기 대조 자료로 사용한다. 기존 계획의 사양서 40건·등록 목록 150건·제품 계열 기준 분리·A~D 비교 평가를 유지한다. 현재 6건을 클래스당 충분한 성능 검증 자료로 간주하지 않는다.
- **확장 기준**: 다른 기자재 클래스의 추가는 이후 확장 후보로 둔다. 기존 클래스의 표현·레이아웃 다양성을 위한 참고 자료 보강은 현재 범위 안에서 진행할 수 있다. 제공되지 않은 별도 채점 기준이 생기면 범위를 재검토한다.
- **산출물**: [이후 단계 가이드](next-steps-guide.md). 기존 W1~W6 일정과 CP-S1~S4를 변경하지 않는다.
- **다음 작업**: W1 온톨로지 속성 정의표 작성부터 시작한다. 이 결정 기록은 온톨로지 구현 또는 평가셋 확정 완료를 의미하지 않는다.

## D-042 · 2026-10-13 · RAG 기반 의미 매핑으로 설계 개편 (사용자 승인 1·2·3)

- **진단(헬퍼, 사용자 지적에서 출발)**: 계획서 5-1의 옛 원칙("LLM은 원문 추출까지, 나머지는 결정론 코드")을 따르다 **의미 해석까지 코드로 밀어냈다**(개발 라벨 사전, 열거 표시형 사전, 범위 토큰화 규칙, 단위 예외 규칙). 그 결과 표기 변형마다 규칙이 늘었고, 가장 어려운 의미 매핑(비고 → 기준·조건·범위)은 풀리지 않았다. 프로젝트의 의도는 이런 영역을 **LLM + RAG 설계로 풀 수 있는지 확인·검증**하는 것이다.
- **결정 1(원칙 5-1 개정)**: 의미 해석(라벨→속성, 표시형→열거 토큰, 비고→기준·조건·범위)은 **검색된 근거와 예시를 받은 LLM**이 한다. 측정·검증(단위 환산, 수치 파싱, 스키마, 근거 위치 확인, 검증 규칙, 중복 식별 일치, 채점)은 결정론 코드가 한다. 표기 변형이 늘면 코드가 아니라 지식 베이스가 늘어난다. G5의 핵심 가설을 "코드 규칙으로 풀기 어려운 의미 매핑을 LLM + RAG가 해결하는가"로 명시한다.
- **결정 2(계획 재편)**: 비교 실험 6-2에 **구성 E(+ RAG 의미 매핑)**를 추가하고, W4에 **W4-R**을 핵심 작업으로 신설한다. W4-2~7(검증기·중복·출력·API)은 RAG 결과를 검증하는 하네스로 병행한다. 세부는 [plans/2026-10-13-w4r-rag-semantic-mapping.md](superpowers/plans/2026-10-13-w4r-rag-semantic-mapping.md).
- **결정 3(첫 실험 범위)**: 한정 정보(기준·조건·범위)부터 시작한다. 효과가 확인되면 같은 지식 베이스로 표시형·라벨 매핑까지 넓혀 개발 사전(코드)의 대체 가능성을 시험한다.
- **사전 검증(헬퍼, 개발 분할만, 같은 계열 제외 leave-family-out, 12계열)**: 한정 정보가 붙은 정답 사실 98개에 대해, 단어 겹침(Jaccard) 검색만으로 가장 비슷한 다른 계열의 정답 줄을 찾았다. 그 예시의 기준·조건·범위가 정답과 정확히 같은 비율은 top-1 **73%**(72/98), top-3 **82%**, top-5 83%다(같은 속성 예시만 검색하면 top-1 75%). 해석은 두 가지다.
  - 검색으로 맞는 예시를 줄 수 있는 상한이 현재 성적(최고 12/97)과 목표(26~55)보다 높다.
  - 다만 합성 생성 규칙 공유로 낙관적일 수 있다. 일반화는 독립 수기 사양서와 테스트 분할(W6)에서만 확인한다.
- **누수 통제(전제)**:
  - 지식 베이스는 개발 분할 정답과 온톨로지 정의로만 만든다.
  - 개발 평가는 같은 계열을 검색에서 뺀다.
