# spec-bridge 착수 체크리스트

작성일: 2026-09-30 · 근거: [착수 리서치](spec-bridge-kickoff-research.md)

> **2026-10-05 계획 v2 재설계([D-001](decisions.md)) 이후 적용 범위**: PRE-01/02(첫 케이스·규제 원문 검증)와 E2(조항 검색)는 확장 과제 FR-14로 이동한다. v2의 대체 항목은 **PRE-01' 온톨로지 범위 결정(D-002)**, **PRE-02' 클래스·속성 목록 확정과 실제 세계 사실 항목의 출처 확인**이다. PRE-03~06, E1, E3(반복 수치 불일치·파싱 실패·`unknown` 사례), E4는 그대로 유효하다.

아래는 **다음 작업의 제안**이다. 기존 로드맵 변경 승인이 아니며, 한 번에 작업 ID 하나씩 진행한다. 모든 실험은 현재 **미실행**이다. W0의 남은 시간에 맞춰 원문 확보를 우선하고, 기술 실험은 필요하면 W1 첫 작업으로 배치한다.

## 착수 전 준비

| 순서·ID | 목표 | 완료 기준(DoD) | 미달 시 처리 |
|---|---|---|---|
| 1 · PRE-01 | 첫 케이스와 적용 판본 선택 | 케이스 1종, 날짜·해역 가정, 선택 원문 목록·판본·위치를 문서화 | 미확정 입력은 `unknown`; 규정 판정용 값으로 추정하지 않음 |
| 2 · PRE-02 | 원문 검토 절차 확인 | 사용자 발췌로 후보 조항 3~5개 구조화, 사용자가 검증자 필드 작성 | 미검증 항목은 운영 규칙에 넣지 않음 |
| 3 · PRE-03 | 수기 POS·추출 구조 검토 | 정상 합성 POS 1건, 반복 수치의 위치 목록, 승인 입력과 문서 관측값 구분 | 스키마·8섹션 초안을 먼저 수정 검토 |
| 4 · PRE-04 | 선행 모듈의 재사용 가능성 점검 | 어댑터·오프라인·감사·평가 모듈 경로, 버전, 인터페이스, 테스트 결과 기록 | ‘재사용 예정’과 ‘사용 가능’을 구분; 일정 재산정 |
| 5 · PRE-05 | 로컬 실행 가설 검증 | 아래 E1·E2 결과표 작성, 설치 버전·모델 digest·입력 해시 기록 | 컨텍스트 축소·순차 상주·4B 비교로 원인 구분 |
| 6 · PRE-06 | 안전한 미판정·근거 검증 경로 확인 | 아래 E3·E4의 통과/실패/미실행과 로그 위치 기록 | 미검증 결과를 적합 판정으로 내보내지 않음 |

사용자에게서 이후 받아야 할 원문 묶음은 **첫 케이스의 선택 문서 발췌 + 문서명·판본·페이지·표/각주 + 케이스 날짜·해역 가정**이다. 전체 문서를 대량 업로드할 필요는 없다. 연구 단계에서는 실제 규제 값이나 보증 성능값을 채우지 않는다.

## 작은 검증 실험

### E1. 메모리·추출·지연

목적: 16GB 조건과 NFR-04의 가능성을 파악한다. 기준 수치는 **프로젝트 실험 제안**이며 규제 수치가 아니다.

| 비교 | 고정 조건 | 기록 |
|---|---|---|
| Qwen3-8B, 4K 컨텍스트 | 고정 영문 섹션, 동일 JSON Schema, 단일 요청 | JSON 파싱 성공, 필드·단위·위치 정확도, wall time, 메모리·swap |
| Qwen3-8B, 8K 컨텍스트 | 긴 입력이 필요할 때만 수행 | 추출 개선 여부와 메모리 증가 |
| 임베딩 상주 / 임베딩 후 언로드 | 같은 검색 결과·LLM 입력 | 로딩 포함 시간, 최대 메모리, 오류 |
| Qwen3-4B, 4K 컨텍스트 | 8B 자원·지연 문제가 있을 때 같은 입력 | 품질 손실과 속도 차이 |

처음에는 합성 섹션 10개, 핵심 필드 10개 정도로 작게 시험한다. 정답은 문서에서 독립적으로 수기 작성한다. 입력마다 한 차례 확인한 뒤 경계 사례만 반복해 변동을 확인한다. 대규모 모델 벤치마크로 확대하지 않는다.

**제안 통과 조건:** 대표 케이스의 필수 수치·단위·위치가 정확하고, 없는 정보는 null/unknown으로 나오며, OOM이 없어야 한다. 섹션 시험만으로 ‘POS 5분 이내’를 통과시키지 않는다. 이후 한 문서 전체에서 모델 로드·검색·추출·판정·재시도 포함 시간을 측정한다.

결과 열: `run_id, input_hash, model_digest, quantization, runtime_version, num_ctx, thinking_mode, input_tokens, output_tokens, load_time, total_time, peak_memory, swap_change, parse_success, field_accuracy, failure_reason`.

### E2. 조항 검색·파싱

목적: 페이지·표·각주가 보존되는지와 한/영 검색이 필요한 근거를 찾는지 확인한다.

1. 사용자 검증 조항을 대상으로 PDF 페이지 번호와 인쇄 번호가 다른 사례, 표 머리글·각주를 포함하는 사례를 대조한다.
2. 정확 ID 조회, 키워드 검색, dense 검색, 하이브리드를 같은 질의로 비교한다.
3. 판본이 다른 유사 조항이 상위에 올 때 잘못 인용하지 않는지 확인한다.

W1의 질의 20개 제안 배분: 정확 식별 4, 영문 의역 4, 한국어→영문 4, 영문→한국어 4, 판본·적용성 hard negative 4. 답이 없는 질의를 포함하면 그 질의는 Recall 분모에서 구분하고 정답 없음 처리율을 따로 계산한다. 실제 정답 ID는 원문 검토 이후 작성한다.

**제안 통과 조건:** 원 계획의 대표 질의에서 올바른 ID가 top-5에 있고, 전체 질의별 순위·실패 사례·Recall@5가 저장되어야 한다. 정답이 여러 개인 질의는 `top-5 내 정답 수 / 전체 정답 수`를 쓰고, 하나라도 찾은 비율인 Hit@5와 구분한다. 단일 질의 성공으로 전체 검색 성능을 주장하지 않는다.

### E3. Citation Guard와 추출 실패

| 사례 | 기대 결과 |
|---|---|
| 존재하지 않는 근거 ID | 최종 판정에서 기각, 원시 출력·원인 기록 |
| 등록되었지만 해당 실행에 제공하지 않은 ID | 허용 집합 검증에서 차단 |
| 올바른 ID지만 적용되지 않는 판본 | 적용성 검토에서 차단·보류 |
| 올바른 ID지만 주장과 무관한 내용 | 화이트리스트의 한계로 검출·평가 대상화; 사람 정답으로 의미 오류 기록 |
| 반복 기재된 수치가 서로 다름 | 모든 출현 위치 보존, 내부 불일치로 보고 |
| 수치 누락·파싱 실패 | `unknown` 또는 추출 오류; 임의값 생성 금지 |
| 같은 규칙에 필요한 날짜가 없음 | 적용 여부 `unknown`; 적합 판정 금지 |
| 외부 규정이 필요 없는 문서 내부 불일치 | 두 문서 위치와 내부 검사 규칙을 근거로 제시 |

**제안 통과 조건:** 각 사례가 기대 상태로 끝나고 기각된 결과가 DOCX·UI·리포트 등 다른 경로로 노출되지 않는다. 의미상 인용 정확도는 별도 사람 검토를 통해 측정한다.

### E4. 오프라인

시험 전 모델·OCR artifact·의존성 준비 단계와 런타임을 구분한다. 실제 통신 관측은 실행 환경에서 가능한 OS/네트워크 격리 방법을 선택한 후 수행한다.

- 준비된 로컬 모델로 생성·검증·내보내기 실행.
- 필수 artifact가 빠진 상태에서 재실행: 다운로드 대신 명시적 실패.
- 잘못된 원격 provider 설정: 시작 또는 호출 전에 거절.
- 실패·재시도·승인 후 재개 경로 실행.
- 앱뿐 아니라 Ollama와 브라우저의 비루프백 통신도 관측.

**제안 통과 조건:** 지정한 테스트 구간에서 외부 통신 시도 0회, 관측 방법·프로세스 범위·예외·로그를 함께 저장한다. 방화벽이 외부 호출을 막았지만 시도 로그가 남으면 ‘차단 성공’으로 기록하고 ‘시도 0회’와 구분한다.

## W1 확장 전 확인

- [ ] 사용자 검증된 조항과 후보 조항을 구분했다.
- [ ] 판본 선택에 필요한 날짜와 적용 근거를 기록했다.
- [ ] 규칙 기준값은 원문 확인 레지스트리에서만 읽는다.
- [ ] 추출값의 모든 문서 위치를 보존한다.
- [ ] 모델·파서·임베딩·검색 인덱스의 버전을 고정했다.
- [ ] 공유 모듈을 실제로 읽고 필요한 인터페이스와 테스트를 확인했다.
- [ ] 정상·결함·비적용·정보 부족 사례가 평가 설계에 포함되어 있다.
- [ ] A~D 실험 정의와 클라우드 미실행 처리 방식을 결정 기록에 남겼다.
- [ ] 이번 체크리스트가 CP-S1을 대신하지 않음을 확인했다.

CP-S1은 원 계획대로 W1 종료 시 30개 조항의 원문 위치·사용자 검증자, 청킹, 검색 평가를 검토한다. 현재는 그 조건에 도달하지 않았다.

## 검토 전달용 요약

- 배경: 영문 주기관 POS를 근거와 함께 생성·검증·변경하는 16GB 로컬 프로젝트.
- 검토 대상: 원 계획과 착수 리서치의 규칙 적용성·증거 구조·평가 수정 제안.
- 핵심 질문: M44 적용 날짜를 맞게 모델링했는가? 내부 불일치 근거와 외부 규정 근거를 나누는가? `unknown`이 누락되는 경로가 없는가? 평가 정답이 검출기 구현과 독립적인가? 오프라인 관측 범위가 충분한가?
- 미해결: 첫 케이스, 원문 발췌·사용자 검증, 선행 모듈 상태, 로컬 성능, 클라우드 예산.
- 상태: 리서치 산출물이며 구현·실험·교차 검토 통과 결과가 아니다.
