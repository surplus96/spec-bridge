# 범위 정의의 결정 후보와 미해결 사항

작성: 2026-10-06 · 상태: 정의표 작성 완료, 실행 정책·사용자 의미 검증 전

아래는 프로젝트 설계 제안이며 실제 업계의 필수 규칙으로 확정한 사항이 아니다. 원본 12건의 문서 식별 검증과 새 속성 관찰·규칙의 사용자 검증은 별개다. 범위 정의 단계는 쟁점을 기록하는 것으로 완료하며 다음 단계가 이 쟁점을 묵시적으로 승인한 것으로 처리해서는 안 된다.

|---|---|---|---|
| U-01 | 펌프 형식별 필수 | 같은 Pump 아래에서 원심식 head, 스크루식 명시 압력 중 1개를 조건부 요구 | 실제 등록 정책 검토; 미지 형식은 review 처리. head/차압/토출압/흡입 head의 동등성 금지 |

## 이번 단계에서 선택한 범위

- 6개 말단 클래스와 기존 계층을 유지한다.
- 의미가 다른 압력·용량·출력·중량을 단어만 보고 합치지 않는다.
- 단위·조건·대상 범위·원문 위치를 보존한다.
- 허용 범위 수치, 제조사 모델 해석 규칙, 일반 단위 별칭 사전을 기억으로 작성하지 않는다.
- 신규 속성 후보와 TC 확장 후보를 기존 평가 라벨에 자동 추가하지 않는다.

## 다음 작업

U-02/U-03/U-05와 클래스별 필수 후보는 [실행 스키마 설계안](schema-design.md)으로 구체화했다(2026-10-06, W1-SCHEMA-DESIGN). 사실 목록·반복 출현, dry/reported 중량, 최대/작동 압력, 후보 구조 검사/등록 준비 검사를 구별한다. 설계안 작성 완료가 이 표의 도메인 의미 검증 또는 정책 최종 승인을 뜻하지 않는다.

현재 세션은 D-006에 따라 데이터셋 완성으로 한정했다. [데이터 작성용 온톨로지 YAML](../../data/ontology/README.md)에 자료형·단위·필수 분기를 기록하고 기존 6건의 표현을 점검했다. 다음은 클래스별 사례 배분과 제품 계열 분할 계획이며, 로더/생성 스키마 구현은 후속 기능 세션이다. 현재 합성 6건에 대한 대조는 정의의 표현 부족을 확인하는 용도로 기록하며, 완전히 독립적인 평가라고 주장하지 않는다.

CP-S1은 온톨로지 v0·정의서·등록 목록을 포함한 W1 전체 산출물 검토 시점이다. 이번 문서 작성만으로 체크포인트에 도달하거나 통과한 것은 아니다.
