# 공통 속성·관계 정의

상태: 범위 정의 작성 완료, 실행 스키마 전 · origin: synthetic

표의 ID·자료형·정규 단위·필수 정책은 프로젝트 설계 후보다. 원본 ID의 제목·판본은 [근거 목록](reference-evidence.yaml)에서 확인한다. 페이지는 PDF 기준이다. 원본 문서의 출현이 해당 속성의 필수성을 증명하지는 않는다.

## Equipment 공통 속성

| ID | 의미·대상 | 자료형 / 정규 단위·차원 | 필수 여부·이유 | 조건·기준 | 근거·확인 상태 |
|---|---|---|---|---|---|
| `maker` | 주 제품 제조사; 발행자·판매자와 구별 | string / 단위 없음 | 필수(안): 제품 식별과 등록 중복 비교 | 명시적인 제조사 근거가 필요; Issued by만으로 일반적인 제조사 동등성을 확정하지 않음 | 원본 12건의 표지·브랜드와 manifest; S: 합성 1.1. 실제 별칭 규칙 사용자 검증 대기 |
| `model_designation` | 특정 주 제품의 형식명 | string / 단위 없음 | 필수(안): 같은 제조사의 제품을 구별 | 제품군 제목과 모델 행 구별; 제조사별 형식명 구조를 기억으로 추정하지 않음 | PUMP-01 p.3, COMP-01 p.10, SEP-01 p.5, 2S-02 p.29, 4S-02 p.8, TC-01 p.2; 관찰 검증 대기 |
| `dimensions` | 명시된 대상 범위의 전체 치수 | object(length,width,height) / mm·길이 | 선택: 식별·비교 보조, 모든 원본에 전체 3축 치수가 있지는 않음 | scope·축 순서 필수; 도면 문자·부분 치수는 원문 근거에 보존, 알 수 없는 축은 미확정; footprint를 전체 치수로 만들지 않음 | PUMP-01 p.5, COMP-01 p.10, SEP-01 p.5, 2S-02 p.30, 4S-02 p.15, TC-01 p.2; 도면 해석 사용자 검증 대기 |
| `dry_weight` | 건조 상태가 명시된 장비/유닛/모듈의 중량 | number / kg·질량 | 선택: 비교 보조; 미기재 또는 상태 불명확 허용 | dry 근거와 scope 보존; ton의 종류가 불명확하면 자동 환산 보류 | 2S-02 p.30, 4S-02 p.15; S: COMP/SEP/TC 4.2. generic Weight의 dry 동등성은 미확정 |
| `reported_weight` | 건조 여부가 명시되지 않은 원문 중량 | number / kg·질량 | 선택·추가 후보: 상태가 없는 실제 표기 보존 | weight_basis는 원문 명시값 또는 unknown; dry_weight와 같은 근거를 이중 사실로 저장하지 않음 | COMP-01 p.10, SEP-01 p.5, TC-01 p.2; 기준 의미 사용자 검증 대기 |

`reported_weight`는 현재 정답에 없는 신규 후보다. 건조 기준을 확인한 같은 관찰은 dry_weight로 정규화할 수 있지만, 단어 Weight만으로 변환하지 않는다. 이 선택은 원본 정보의 손실을 줄이기 위한 프로젝트 정책이며 W1 구현 시 중량의 단일 객체 모델과 비교 검토한다.

`dimensions`의 관찰은 부분 축을 보존할 수 있도록 설계하되, 현재 평가 정답은 세 축이 완전한 객체다. 부분 관찰과 완전한 등록 값의 검증 계약을 구별한다.

## 중간 계층의 공유 후보

| 계층 | 공유 속성 | 정책 |
|---|---|---|
| Engine | rated_power, rated_speed, number_of_cylinders, fuel_types | 두 엔진 정의표에서 의미·기준을 확인; 실린더당 출력과 전체 출력 구별 |
| FluidMachinery | medium, motor_power | 매체는 주 제품이 처리하는 물질; 출력은 구동 전동기의 정격으로 명시된 경우만 motor_power |
| EngineComponent | 공통 고유 속성 추가 없음 | 현재 Turbocharger만 있으므로 근거 없는 공통 속성을 만들지 않음 |

## 관계

| ID | 의미·자료형 | 필수 여부·이유 | 조건·근거 |
|---|---|---|---|
| `manufactured_by` | Product → Manufacturer, 식별 가능한 제조사 참조 | 필수(안): maker와 일치하는 제품 식별 연결 | 프로젝트 관계 설계. maker가 unknown이면 관계도 미확정; 제조사 레코드를 이름만으로 임의 병합하지 않음 |
| `has_component` | Product → Product, 식별된 품목의 **공급 범위(BOM) 포함** 관계([D-014](../decisions.md)). 물리적 부착·기계적 호환성·장비 선정을 뜻하지 않음 | 선택: BOM·구성품이 명시된 경우 | S: 2S의 TTA-70. 형식 없는 pump/heater 언급은 원문에 보존하되 확정 제품 관계로 만들지 않음 |
| `variant_of` | Product → Product, 명시적 또는 사전 정의된 변형 계열 관계 | 선택: 제품 계열 구별 | 프로젝트 관계 설계. 유사도 점수만으로 관계를 확정하지 않음; 현재 6건에 양성 근거 없음 |
| `external_ref` | 외부 분류 체계의 코드·판본·출처 | 선택/계획된 작업 | Gmod 코드는 다음 단계에서 원본 데이터 조회 후 연결; 현재 코드 미기입 |

관계 ID는 산업 표준 관계라고 주장하지 않는다. 순환 관계 허용 여부, 같은 자연키 충돌, 미확정 제조사 처리, variant 계열의 기준은 [미해결 사항](open-issues.md)에서 추적한다.
