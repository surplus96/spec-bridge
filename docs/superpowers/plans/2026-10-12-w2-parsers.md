# W2 파서와 원문 위치 보존 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (교육 모드 — 사용자가 타이핑하고 헬퍼는 실패 테스트·설명·조각·검증을 맡는다). 서브에이전트 실행은 사용자가 요청할 때만. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PDF·Excel·DOCX 사양서를 LLM 없이 읽어, 값이 나온 위치(페이지·좌표 / 시트·셀 / 문단·표 칸)를 보존한 블록 목록으로 바꾼다.

**Architecture:** 형식별 파서 3개가 공통 `ParsedDocument`(블록 목록)를 반환하고, 확장자 디스패처가 하나의 입구 `parse_document()`를 제공한다. 위치는 W1의 `spec_bridge.ontology.facts.Location`을 그대로 써서 정답 위치와 같은 좌표계로 비교한다. 파싱 실패는 예외로 프로세스를 죽이지 않고 `ParseError`로 보고해 W3에서 `unknown` 처리한다.

**Tech Stack:** Docling(PDF 구조·좌표) + pypdfium2(PDF 원문 글자, D-024), openpyxl(Excel), python-docx(DOCX), Pydantic v2, pytest

**Spec:** [프로젝트 계획 W2·FR-05·NFR-01·리스크 표](../../spec-bridge-project-plan.md), [D-020](../../decisions.md)(W2 범위 축소), [착수 리서치 §python-docx·Docling](../../spec-bridge-kickoff-research.md), [정답 계약](../../../data/synth/answer-contract.yaml)(위치 표기)

## Global Constraints

- 데이터셋 v1 불변: `shasum -a 256 -c data/synth/SHA256SUMS` 실패 0.
- 위치 정확도 측정과 튜닝에는 **개발 분할 24건의 정답만** 쓴다. 테스트 분할 16건은 "오류 없이 파싱되고 모든 블록이 유효 위치를 갖는가"만 확인하고 정답을 읽지 않는다(D-020 연장).
- 파서는 LLM·네트워크를 쓰지 않는다. Docling 모델은 미리 받아 두고 테스트는 `HF_HUB_OFFLINE=1`로 실행한다(NFR-01).
- 파서는 원문을 **정규화하지 않는다**(공백 정리·단위 변환·별칭 치환 금지). 정규화는 W3다.
- 커밋·푸시는 사용자 요청 시에만. 완료 판정은 `uv run pytest`, `uv run ruff check .`, `uv run mypy spec_bridge tests`로만(W2-6부터 tests 포함).

## Review Focus

1. **DOCX 수정 추적**(`w:ins`/`w:del`): python-docx가 내용을 놓칠 수 있다(리서치). 조용히 빠뜨리지 말고 `ParseError("tracked changes")`로 보고 → Task 4 테스트.
2. **PDF 좌표 원점**: Docling bbox가 위-왼쪽 원점이면 정답(ReportLab, 아래-왼쪽 원점)과 어긋난다. 변환 후 정답 bbox 중심이 블록 안에 들어와야 한다 → Task 5 테스트.
3. **빈 칸·`—` 칸**: 엑셀/표의 빈 칸으로 유령 블록을 만들지 않고, `—`처럼 글자가 있는 칸은 그대로 블록이 된다 → Task 3 테스트.
4. **손상·미지원 파일**: 잘린 파일, 모르는 확장자는 프로세스를 죽이지 않고 `ParseError`(원인 포함) → Task 2 테스트.
5. **유니코드 원문 보존**: `×`, `—`, `m3/h`, `FAD*` 같은 원문 글자가 바뀌지 않아야 정답 `raw_text`와 대조된다 → Task 3~5의 위치 회수 테스트가 `raw_text` 포함 여부로 검사.

### Task 2 (W2-2): 정답 위치 대조 도우미

**Files:** Create `tests/parse/__init__.py`, `tests/parse/conftest.py`

위치 회수(recall) = 개발 정답의 관찰 중, **같은 위치의 블록이 있고 그 블록 텍스트에 `raw_text`가 들어 있는** 비율. 형식별 같은 위치 판정:

```python
def same_place(gold: dict[str, Any], block: Block) -> bool:
    loc = block.location
    if gold.get("pdf_page") is not None:              # PDF: 같은 페이지 + 블록(글자) 중심이 정답(레이아웃) 영역 안
        gx0, gy0, gx1, gy1 = gold["bbox"]
        bx0, by0, bx1, by1 = loc.bbox or (0, 0, 0, 0)
        cx, cy = (bx0 + bx1) / 2, (by0 + by1) / 2
        tol = 2.0
        return loc.pdf_page == gold["pdf_page"] and gx0 - tol <= cx <= gx1 + tol and gy0 - tol <= cy <= gy1 + tol
    if gold.get("sheet") is not None:                 # XLSX
        return loc.sheet == gold["sheet"] and loc.cell_ref == gold["value_cell"]
    if gold.get("table") is not None:                 # DOCX 표
        return (loc.table, loc.row, loc.column) == (gold["table"], gold["row"], gold["cell"])
    return loc.paragraph == gold.get("paragraph")     # DOCX 문단


def recall(parsed: ParsedDocument, answer: dict[str, Any]) -> tuple[int, int, list[str]]:
    """(found, total, missing observation ids) over the answer's observations."""
```

`dev_documents(file_format)`는 W1 conftest의 매니페스트 도우미로 개발 분할의 (input_id, 입력 경로, 정답)을 돌려준다. 테스트 분할 정답은 읽지 않는다.
