### T2 · 최종 판정 CLI 분리 (R6)

- `compare.py`에 분할별 기준을 둔다.
  - `dev`: D-048(지어낸 문맥 ≤ 16, 문맥 TP ≥ 50)
  - `test`: D-080((b) ≤ 10, 목표권 `ceil(0.515 × 문맥 키)`)
  - `handwritten`: (c)와 목표권만. (a)·(b)는 판정하지 않고 수치만 낸다
- 분할은 `run.json`에서 읽는다. 세 실행의 분할이 다르면 거부한다.
- 실패 테스트를 먼저 쓴다.
  - 테스트 분할에서 FP 11이면 (b) 불통과
  - TP 38이면 목표권 통과
  - 수기에서는 (a)·(b)의 판정 키가 없음
- **DoD**: 실제 테스트 실행에서 `limit 10`, `target 38`, 결과는 보고서와 같다. 수기에서는 target 7이다.

### T3 · 재현 manifest와 동결 범위 명시 (R5)

- 기존 `FREEZE.json`과 `verify()`는 그대로 둔다(W6 기록 보존).
- 새 `spec_bridge/eval/manifest.py`를 만든다.
  - 동결 목록 밖이지만 결과에 영향을 주는 것을 기록한다. 대상은 `service.py`, `normalize/`, `parse/`, `pipeline.py`, `extract/` 전체, `rag/settings.py`, `uv.lock`이다.
  - 실제 입력·정답 파일 해시를 `SHA256SUMS`와 대조한다.
  - 파싱 산출물(`var/parsed/*`) 해시를 기록한다.
- W6 평가에 대한 manifest는 git으로 근거를 남긴다. 동결 커밋 `5494f33`에서 계산한 해시와 현재 해시가 같으면 "동결 시점과 같음"으로 기록한다. 결과는 `docs/reports/w6-repro-manifest.json`이다.
- **앞으로의 동결**에는 이 목록을 함께 넣어 바뀌면 거부한다. 단순 기록할 항목(모델 digest, 파싱 산출물)과 거부할 항목을 문서에 구분한다.
- 보고서 §2와 패키지 표현을 고친다. "`freeze verify` 통과 = 동결 목록 파일이 같음"으로 한정한다.
- **DoD**: 임시 사본에서 `RAG_K`를 바꾸면 manifest 검사가 실패한다(테스트). `w6-repro-manifest.json`에서 W6 시점과 현재가 일치한다.

### T4 · 새 환경 재현 절차 (R2)
