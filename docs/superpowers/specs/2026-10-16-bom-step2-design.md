# BOM 2단계 설계: 검토 화면 연동 (D-103)

2026-10-16 · 상태: **승인**(사용자 "권장안으로 모두 진행", 결정 1~7 모두 권장안) · 근거: D-101

| # | 결정 | 내용 |
|---|---|---|
| 1 | 화면 | 새 BOM 화면 `#/boms`(목록 화면의 "BOM 연결"). 제품 상세에는 구성품·상위 제품 목록 |
| 2 | 흐름 | 업로드 → 미리보기(행마다 상태·사유) → 적용. 업로드만으로는 쓰지 않는다 |
| 3 | 오래된 미리보기 | 적용할 때 서버가 다시 계획한다. 미리보기의 `plan_key`와 다르면 409로 거부하고 화면이 새 미리보기를 받는다 |
| 4 | 검토 대기 행 | 담당자가 행의 클래스(하위 클래스 포함)의 등록 제품을 골라 사유와 함께 지정한다. 기록은 `decided_by: reviewer`로 규칙 식별(`rule`)과 구분한다 |
| 5 | 저장소에 없는 제품 | 만들지 않는다. 같은 종류의 등록 제품이 없으면 "사양서를 먼저 등록" 안내만 보인다 |
| 6 | 제품 상세 | `components`(마지막 BOM 적용의 수량 포함)와 `parents` |
| 7 | 파일 보관 | `<앱 폴더>/boms/<BOM-UP-해시12>/<원래 이름>`. 같은 파일은 첫 사본을 쓴다. 적용 이벤트에 `bom_id`·`file_name`·`sha256` |

## API

- `POST /api/boms`(파일) → `BomView`(쓰지 않음). 형식 415, 빈 파일 400, 읽기 실패·상위 제품 없음 422.
- `GET /api/boms/{id}`, `POST /api/boms/{id}/preview`(`picks`) → `BomView`.
- `POST /api/boms/{id}/apply`(`plan_key`, `picks`) → `BomView`(`added`). 계획이 바뀌었으면 409, 맞지 않는 지정은 422.
- `GET /api/products/{id}`에 `components`·`parents`.

## 범위 밖

비정형 행 매핑(G5 보류, D-102), 관계 삭제·수정 화면, 호환성 판단(D-014).
