# 모델·데이터 카드

spec-bridge가 쓰는 모델과 데이터, 평가 방법, 사용 범위를 한곳에 모았다. 수치의 출처는 [W6 최종 평가 보고서](reports/w6-final-evaluation.md)다.

## 1. 시스템 개요

| 항목 | 내용 |
|---|---|
| 용도 | 선박 기자재 제품 사양서에서 온톨로지 속성 사실을 추출·검증하고, 담당자 검토 뒤에 등록한다 |
| 운영 구성 | E1SV: LLM 분류 → LLM 값 추출(원문 그대로) → 결정론 정규화 → 값마다 문맥 RAG 체인(사례 3개) + 근거 구절 코드 검증 + Self-RAG 지지 판정 + 속성 충돌 해소 → 검증 E1~E5 → 중복·유사 검사 → 사람 검토 |
| 사용자 | 단일 담당자, 로컬 컴퓨터(`127.0.0.1`) |
| 결정권 | 사람. 시스템은 빠진 값을 채우지 않고, 자동 병합하지 않는다 |

## 2. 모델

| 역할 | 모델 | 설정 | 비고 |
|---|---|---|---|
| 분류·추출·문맥 해석 | `exaone3.5:7.8b` (Ollama, digest `c7c4e3d1ca22`) | temperature 0, seed 7, num_ctx 8192 | 모든 W6 평가 실행이 같은 digest. 같은 입력의 반복 실행 결과가 같다(잡음 0, D-038, D-087) |
| 임베딩(사례 검색) | `bge-m3` (Ollama, 1024차원) | BM25와 하이브리드 | `nomic-embed-text`와 비교해 선택(D-047) |
| 비교용 클라우드 | `gpt-4o-mini` | 개발 분할 비교와 W5 화면 시연에만 사용 | 테스트 분할에는 쓰지 않았다(테스트 문서 외부 전송 미승인, D-080) |

- 모델 라이선스와 사용 조건은 각 배포처에서 확인해야 한다. **[미검증]** 이 저장소는 모델 가중치를 포함하지 않는다.
- 하드웨어: Apple Silicon Mac, RAM 16 GB. 문서당 지연은 테스트 E1SV 기준 약 83초이고, LLM 호출은 문서당 약 16회다.

## 3. 데이터

모든 데이터는 **합성**이다(`origin: synthetic`). 실제 제조사·제품·규격 값이 아니다.

| 데이터 | 수량 | 내용 |
|---|---|---|
| 합성 사양서 | 40건 (개발 24 · 테스트 16) | 6개 클래스. 개발은 클래스마다 4건, 테스트는 2~3건. 형식은 PDF 20 · XLSX 12 · DOCX 8 |
| 정답 | 40건 | 관찰(원문 위치), 사실(값 + 기준·조건·범위), 오류(E1~E5), 필수 누락, 중복·유사 관계 |
| 사례 구성 | — | 정상 10 · 오류 E1~E5 20 · 중복 6 · 유사 4. 레이아웃은 표 18 · 혼합 15 · 서술 7 |
| 등록 제품 목록 | 개발 90 · 테스트 60 | 중복·유사 판정 대상. 분할마다 자기 목록만 쓴다 |
| 해결 사례 KB | 234사례 | **개발 정답만**으로 만든다. 테스트 계열 0건(테스트로 확인). 평가 때는 질의 문서와 같은 계열의 사례를 검색에서 뺀다 |
| 수기 사양서 | 6건 (Markdown) | 생성기 밖 표기를 보는 보완 세트. 정답 사실 56개, 관찰 98개 |
| 참고 제조사 문서 | 12건 (저장소에 없음) | 레이아웃·속성 이름 참고용으로 로컬에서만 읽었다. 목록만 `data/reference/manifest.yaml`에 있다 |

- **분할**: 제품 계열 기준(계열 24개)으로 나눴다. 테스트 분할은 W6 동결 뒤 한 번만 실행했다(D-020, D-080).
- **수기 사양서의 독립성**: 헬퍼 모델이 초안을 썼고(`reviewed_by: null`), 온톨로지·사전을 만들 때 열람했다. 변환 과정에 헬퍼 판단 3종이 들어갔다(D-082). 독립 평가로 인용하지 않는다.

## 4. 평가 방법

- **사실 F1**: 정규화한 값과 기준·조건·범위가 모두 정답과 같아야 맞는 것으로 친다. micro 집계다.
- **문맥 키**: 기준·조건 또는 기본값이 아닌 범위가 있는 정답 키다. **지어낸 문맥**은 정답에 없는 문맥을 단 예측 키의 수다.
- **G3**: 주입한 오류(E1~E5)의 재현율이다. **G4**: 라벨된 중복·유사 쌍의 재현율과 정밀도다.
- **판정**: 사전 등록 기준(D-080)을 쓴다. 문서 단위 쌍체 부트스트랩 10,000회, seed 7이다.
- **동결**: 채점기 `f9b6e223cb15`, 프롬프트·RAG 모듈, KB, 온톨로지, 개발 사전, 수기 세트를 해시로 고정했다(D-086).

## 6. 지름길 기준선 (반드시 함께 인용)

같은 생성 규칙에서 나온 합성 데이터라 쉬운 지름길이 있다(D-018 독립 감사).

- 개발 라벨 사전만으로 테스트 관찰의 **91.6%**를 속성에 대응할 수 있다.
- 모델명 시리즈 접두사 규칙만으로 유사 판정의 정밀도와 재현율이 1.0이 된다.
- 제조사명 접미사(A/B 개발, C/D 테스트)가 분할과 일치한다.
- 분류 top-1 1.0은 키워드 지름길의 영향을 받는다(W3 보고서 §4).

그래서 G2·G4의 높은 수치는 이 데이터셋의 성질이 큰 몫을 한다. 이 프로젝트의 핵심 주장은 **문맥 해석(G5)**에 대한 것이고, 그 근거는 규칙 기준선 R(문맥 키 0)과 같은 모델의 E0(문맥 키 4) 대비 차이다.

## 7. 사용 범위와 한계

- **의도한 사용**: 합성 데이터로 설계를 시연하고 평가한다. 실제 등록 업무에 쓰려면 실제 마스터 데이터(제조사 별칭, 용어 사전, 허용값)와 원문 출처 검증(`verified_by`)이 필요하다.
- **알려진 실패**
  - 정규화 사전 밖 표기는 읽지 못한다. 검토 화면 경고로 담당자에게 간다(D-091).
  - 문서 구절형 범위(`complete … including …`)를 잘 채우지 못한다.
  - 소형 모델이 문서에 있는 값을 가끔 빠뜨린다. 테스트에서 6건이었다.
- **사람 수정은 검증하지 않는다.** 원문과 다른 값을 입력해도 정규화·검증을 통과하면 등록된다. 사유와 이력으로 책임을 남긴다.
- **오프라인 보장 범위**: 앱과 모델 서버의 외부 연결 0을 관찰했다. 모델 최초 다운로드와 Ollama 데스크톱 앱의 자체 통신은 범위 밖이다(보고서 §9).
