# G5 후속 실험: BOM 행 → 등록 제품 매핑 (D-107~D-111)

2026-10-19(해석 정정 2026-10-19, D-114) · 판정: **사전 등록 기준 (c) 미달, G5 가설 불성립**(사용자 확인, D-111) · 결론 범위: 선박 기계 목록에서 관찰한 표기 패턴 안에서, 합성 등록 제품에 대해(D-105)

## 1. 질문과 설계

- **질문**: 표기가 제각각인 BOM 행을 등록 제품에 연결할 때, 해결 사례를 검색해 쓰는 LLM(E)이 결정론 규칙(R)과 사례 없는 LLM(C)보다 나은가(G5 핵심 가설을 BOM으로 확장).
- **과제**: 행 하나(구성품 클래스, 모델 칸, 제조사 칸, 수량 칸) → 등록 제품 하나 또는 "없음".
- **데이터(합성, D-109)**:
  - 등록 제품을 수집한 표기 패턴(출처 8곳, 서명된 패턴 12개, D-105·D-106)으로만 다시 적었다.
  - 출처 단위로 분할했다: 개발은 BOMSRC-01~04, 테스트는 05~08이다. 테스트에만 있는 패턴은 PAT-09(일련번호)·PAT-10(동등품)이다.
  - 개발 120행(제품 90, "없음" 30), 테스트 80행(제품 60, "없음" 20).
  - 정답 규칙: 행이 등록 모델 전체와 그 제조사의 어떤 표기를 담으면 그 제품이 정답이다. 모델 없음·구동기·미등록 모델은 "없음"이다.
- **구성**:
  - R: D-108 결정론. 확실할 때만 연결하고, 동등품·제조사 표기 차이는 대기로 둔다.
  - C: 로컬 `exaone3.5:7.8b`에 BM25 후보 10개를 준다.
  - E: C에 해결 사례 3개를 더한다(BM25 + bge-m3 RRF).
  - C·E 공통: 고른 후보의 모델 코드가 행에 있고 클래스가 맞을 때만 받아들인다(D-110).
- **판정 기준(D-109, 테스트 생성 전 등록)**: 쌍체 부트스트랩 10,000회, seed 7.
  - (a) E − R 정확도 하한 > 0.
  - (b) E 잘못 연결률 ≤ 5%, 그리고 R + 2%p 이하.
  - (c) E − C 정확도 하한 > 0.
- **동결**: `docs/reports/g5-freeze.json`. 2026-10-18T23:35Z, 파일 12개, 모델 digest `1b48a3a1c175…`.

## 3. 해석

교차 검토(D-113)를 반영해 정정했다(D-114). 정정 전 문장은 이 절 끝의 "정정 기록"에 남겼다. 수치와 판정은 바뀌지 않았다.

- **관측된 구성 간 차이**: 이번 합성 테스트에서 C·E는 사전 지정한 R보다 정확도가 +0.31 높았고(1.000 대 0.688), 잘못 연결은 셋 모두 0이었다.
  - R이 놓친 25행은 모두 제조사 표기 차이(16행) 또는 동등품(13행)을 포함한다(겹침 있음). 테스트에만 있던 PAT-09·10 행도 C·E는 모두 맞혔다.
- **이 차이를 LLM의 의미 해석 기여로 읽을 수 없다(F1)**:
  - 사후 진단(테스트 공개 뒤, 판정에 쓰지 않음)을 했다. 같은 BM25 후보 10개에서 코드 검증(모델 코드가 행에 있고 클래스가 맞음)을 통과하는 후보가 정확히 하나면 그 제품, 없으면 "없음"으로 답하면 개발 120/120, 테스트 80/80이다. LLM도 제조사 판단도 필요 없다.
  - 합성 등록 제품은 모델 코드가 모두 달라서, 제조사를 다르게 써도 모델 코드와 클래스로 정답이 정해진다.
  - 따라서 R과 C·E의 차이는 수락 정책의 차이를 함께 담는다. R은 제조사가 맞아야 연결하고 동등품은 대기로 둔다. C·E는 검증만 통과하면 받아들인다.
  - 이 진단 규칙을 기준선으로 바꾸거나 제품에 적용하자는 뜻은 아니다. 제조사를 보지 않는 연결은 실제 데이터에서 위험하다.
- **사례 검색(E)**: 이번 합성 과제의 최종 정확도에서 C 대비 추가 효과는 관측되지 않았다. C가 이미 80행을 모두 맞혀 차이가 날 여지가 없었다(천장 효과). C와 E의 최종 답은 80행 모두 같다. 검증 전 모델 답은 11행이 달랐다. 차이 0은 두 구성이 일반적으로 같다거나 사례 검색이 쓸모없다는 증거가 아니다.
- **"없음" 판단은 대부분 코드가 교정했다**:

  | 테스트 구성 | 검증 전 정답 | 검증 거부 | 최종 정답 | "없음" 정답 행에서 모델 자체가 "없음" |
  |---|---:|---:|---:|---:|
  | C | 63/80 | 17 | 80/80 | 3/20 |
  | E | 61/80 | 19 | 80/80 | 1/20 |

  - 거부는 모두 "없음" 정답 행에서 나왔다. 제품 정답 60행은 검증 전에도 모두 맞았다.
  - 이 문제는 개발 단계에서 발견해 동결 전에 고쳤다(D-110). 변경 전 개발 결과는 C 잘못 연결 16.7%, E 25.8%다. 코드 검증은 개발 결과를 보고 넣은 알고리즘 변경이며, 측정 대상은 순수 LLM이 아니라 LLM + 검증 파이프라인이다.
- **R의 점수는 정답 규칙의 영향을 받는다**:
  - 동등품 행(13행)은 D-108 안전 정책상 R이 대기로 두지만, D-109 정답 규칙에서는 그 제품이 정답이다.
  - 동등품 행을 빼면 R 정확도는 0.821(55/67)이다. 같은 부트스트랩으로 E − R은 +0.179 [0.090, 0.269]다(민감도 분석, 본 판정 대체 아님).

**정정 기록(D-114)**: 정정 전 §3은 "LLM 해석 + 코드 검증은 규칙보다 낫다", "모델이 같은 제조사의 다른 표기를 읽었고", "해결 사례 검색(E)의 추가 효과는 없다", "지시문만으로는 7.8B 모델이 '없음'을 답하지 않았다"고 적었다. 앞의 둘은 F1에 따라 입증되지 않은 해석이다. 셋째는 범위가 넓었다. 넷째는 절대 표현이었다(실제로는 3/20, 1/20).

## 4. 한계

- **합성 데이터**: 모델명이 규칙적이고(`VX###-###`), 제조사가 분할마다 2곳뿐이다. C가 천장에 닿은 것은 과제가 쉬웠기 때문일 수 있다. 실제 BOM 성능으로 읽지 않는다.
- **표기 출처**: 수집한 실제 행은 43개(출처 8곳)이고, 상위 제품은 엔진이 아니라 선박이다(D-105). 패턴만 옮겼으므로 실제 행의 분포를 재현하지 않는다.
- **모델**: 로컬 `exaone3.5:7.8b` 하나다. digest가 W6 평가(`c7c4e3d1ca22…`)와 다르다(D-110).
- **개발 단계 변경**: 코드 검증과 사례 제외를 개발 결과를 본 뒤 넣었다(D-110, 동결 전). 판정 기준은 바꾸지 않았다.
- **개발과 테스트의 같은 천장**: 개발에서도 C·E가 120행을 모두 맞혔다. 그래서 (c)가 테스트에서 성립하기 어렵다는 것을 동결 전에 알았고 기록했다(D-110).
- **합성 데이터가 LLM 기여를 가르지 못한다(F1)**: 모델 코드가 제품마다 달라 코드 검증만으로 답이 정해진다. 같은 모델 코드를 여러 제조사가 쓰는 데이터가 있어야 제조사 판단의 기여를 잴 수 있다.
- **동결 검사의 범위(F2)**: `freeze verify`는 파일 해시만 본다. 생성 모델 digest, 추론 옵션, 임베딩 모델 digest의 변경은 막지 않는다. 이번 C·E 실행의 생성 모델 digest는 동결 기록과 같다(실행 기록으로 확인).
- **순서 증명의 범위(F3)**: D-109와 테스트 데이터는 같은 커밋(`56adddf`)에 처음 기록됐다. 등록이 생성보다 먼저였다는 것은 결정 기록의 진술이다. `run.json`의 시각은 실행 종료 시각이다. C·E 호출이 동결 뒤였다는 것은 로컬 감사 기록(프롬프트 해시 대조, 공개 묶음에 없음)으로 확인했다(D-113).
